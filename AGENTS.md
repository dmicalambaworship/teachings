# DMI Calamba City Teachings

## Workflow (every change)

- Work on a branch `codex/<change-slug>`. Never push directly to `main`.
- Code and test locally first: `npm run check` (0 errors) then `npm run build` (all routes generate).
- Commit with conventional prefixes (`feat|fix|perf|chore(studies|specials|events|seo|pages): ...`), push, open a PR for review. Do not self-merge; `main` auto-deploys to GitHub Pages.
- Never add AI attributions: no "generated by <tool>", AI credits, or bot voice anywhere in copy, meta, comments, or docs. Content must read as church-owned.

## Site setup

- Static Astro site; `.github/workflows/deploy.yml` deploys `main` to GitHub Pages.
- Production is `https://dmicalambacity.org/`. In `astro.config.mjs` keep `site: 'https://dmicalambacity.org'`, `base: '/'`, `trailingSlash: 'always'`; never restore the old `github.io/teachings` base.
- Build internal URLs and asset paths from `import.meta.env.BASE_URL`.
- Use only `BaseLayout`, `LanguageToggle`, `SocialLinks`. All styles live in `src/styles/global.css` — no page-local CSS. Canonical + social metadata render in `BaseLayout.astro`.

## English / Taglish contract

- Every content page offers complete English (HTML default) and Taglish via `LanguageToggle.astro`. No page-specific toggle scripts.
- Taglish strings go in the page's `translations` object, one key per translatable `data-i18n` element; missing keys unacceptable.
- Translate a11y with `data-i18n-aria-label` / `data-i18n-alt`; switch element `lang` with `data-i18n-lang` (Scripture and citations).
- Toggle uses `en`/`fil`, updates document language, remembers choice in `dmi-study-language`.
- Keep branded English titles in Taglish when natural (e.g. "Dig Deep — Pakikipagbuno sa Diyos").

## Content types

### Bible Study — `src/pages/YYYY-MM-DD-slug/index.astro`

- Template: the newest study (currently `2026-09-06-altar-of-our-church`). Preserve its structure:
  cover link → hero (nav with date + toggle, eyebrow, title, subtitle, Scripture blockquote) → `study-content`: `study-aside` (Theme, Key texts, Time, Canva presentation, Sunday service, Facebook Live) + `study-article`: numbered sections 01→N with `discussion-prompt`s, `verse-card`s, response steps, closing prayer, takeaway, `qr-section`, `scripture-notice` → footer.
- Covers: `picture` with webp `srcset` (1280w + 2400w) + jpg fallback; store `public/YYYY-MM-DD-slug-cover.jpg`, `-1280.webp`, `-2400.webp`.
- QR: `public/qr/YYYY-MM-DD-slug.png` for the public article URL; `qr-section` links both the QR image and the page URL.
- Summary links are article-specific: Canva presentation, YouTube service, Facebook Live video. Never placeholders; never reuse another study's URLs.
- Home (`src/pages/index.astro`): newest study featured, older in reverse-chronological order.

### Specials — `src/pages/specials/`

- Single-resource pages (e.g. `20260912-dig-deep-wrestling-with-god/`): `specials-hero`, `study-content specials-content`; the aside carries the download block (poster image wrapped in a PDF link `.specials-resource-figure-link`, plus `.resource-download-button`).
- `specials/index.astro` lists resources via `.specials-list` (meta · title · blurb · action).
- Same bilingual contract as studies; each special's links point to its own resource (PDF / video), not a previous item's.

### Events — `src/pages/events/`

- Event pages (e.g. `20260916-dmi-18th-anniversary/`): `events-hero`, `study-content events-content`; program sections (Day 1 / Day 2), video via YouTube embed iframe (`https://www.youtube-nocookie.com/embed/<ID>`) inside `.video-embed` (16:9) plus `.video-links` (YouTube / Facebook).
- `events/index.astro` lists events via `.events-list`.
- `.events-*` rules share the `.specials-*` styles through grouped selectors in `global.css`.

## Images & social sharing

- Per-page social metadata (BaseLayout props):
  - Item pages (study, special, event) → their own `socialImage` jpg: study cover jpg (2400×1350) for studies, poster-derived jpg for specials, saved YouTube thumbnail jpg for event videos. Set matching `socialImageAlt/Width/Height`.
  - Listing pages (`specials/index`, `events/index`) and home → default `dmi-calamba-social-preview.jpg` (1280×720). Do not promote an item's graphic to a listing page.
  - Event pages with video → also pass `socialVideo` (YouTube watch URL); `BaseLayout` emits `og:video` + `twitter:player` so FB/LinkedIn embed a player.
- OG images must be jpg (Facebook crawler compatibility). Derive from webp/png with `sips -s format jpeg -s formatOptions 80 -Z 1280 in --out out.jpg`.
- Display images: convert PNG → WebP first (`cwebp -q 78 -m 6 in.png -o out.webp`); keep mobile-fast (~≤300KB).
- Facebook caches previews: after deploy, re-scrape changed URLs in the Sharing Debugger (https://developers.facebook.com/tools/debug/) → "Scrape Again".
- External links open with `target="_blank" rel="noreferrer"`. Shared social/channel URLs live only in `SocialLinks.astro`.

## Before pushing a PR

- No `/teachings/` or `dmicalambaworship.github.io` URLs anywhere (grep src + dist).
- `npm run check` → 0 errors; `npm run build` → new routes listed; verify homepage link, both languages, external links, and og meta in `dist/`.
- PR body: summary, files, validation run, review notes (e.g. pending links, cache scraping).
